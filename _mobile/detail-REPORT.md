# detail.html — mobile pass report

## Done
- **Forced `.reveal` to permanent `opacity:1; transform:none` on mobile** — `renderDetail()` tags every `.dt-block` (each image+text beat of the case study) with class "reveal" and only removes `opacity:0` once an IntersectionObserver flips `.in`. The baseline capture showed the hero photo/caption, then a large blank gap all the way to "What I take from it" — every `.dt-block` never appeared. Now guaranteed visible regardless of scroll timing. Visible: the whole body of the case study, between the hero photo and the "What I take from it" takeaways list — previously blank space (`.dt-takeaways` itself isn't reveal-gated, which is why it and the footer already showed in the baseline).
- "← Inspiration" back link: added real padding (was text with no padding at all, tap height ~14px) so it hits the 44px floor; trimmed the margin-top by the same amount so it keeps the same visual distance from the nav/world-band. Visible: screen 1, just under the world-band pill.
- "Visit ___ →" source CTA: was already close to the 44px floor (15px padding + ~14px line-height ≈ 44.4px) — added an explicit `min-height:44px` so it doesn't depend on font-metric rounding across browsers. Visible: under the lede, when the case study links out.
- Bumped the shared "back to the tower" pill (`.wback`, injected by `site-nav.js`) from 9.6px to 14px, scoped to this page only — matches the fix already shipped on resources.html for the same shared element. Visible: the pill over the world-band illustration, screen 1.

## Proposed (not done)
- The reveal-on-scroll bug (see Done) is patched defensively via CSS; the root cause is the `IntersectionObserver` in `renderDetail()` (app.js, threshold 0.12, no width check) — worth a real JS fix so desktop/tablet don't rely on the same silent failure mode. Out of scope for a CSS-only pass.
- The world-band's zero-height wrapper is inserted right after `.snav` and sits *behind* (`z-index:-1`) whatever content follows in flow — by design, meant to work like a hero background under an actual hero image. On detail.html the first thing in flow is plain text (`.back` + `.dt-kind`/`h1`/`.dt-meta`), not an opaque image, so the top ~40-60px of that text may render directly over the vivid, un-faded part of the painted illustration before `.wveil`'s gradient has darkened it. Couldn't confirm visually — the baseline screenshot doesn't show the "← Inspiration" text at all near the top, which is *consistent* with a contrast problem but not proof of one (the brief excludes running a live audit to check). Flagging rather than adding an unverified pill/background treatment, since that would be a legibility/design call, not a resize-or-reposition fix, and the same layering exists on any other page whose first in-flow content is text rather than an image.

## Flags
- `div.wmedia` / `img` overflow in report.json (-12px to 402px against a 390px viewport) comes from the shared `site-nav.js` world-band parallax bleed (`inset:-7% -3%` by design), not from detail.html or data.js. `docOverflowX:0` in the same report confirms it's clipped by `.wband{overflow:hidden}` and doesn't produce a real scrollbar — a script false-positive on the child's unclipped bounding box, not a visible bug. Same conclusion already reached independently on design.html, about.html and inspiration.html.
- See "Proposed" above re: possible low-contrast overlap between the `.back` link/header text and the world-band illustration — worth a real render check.
- Not verified live (brief excludes running the audit): whether the reveal fix above fully resolves visually, since the baseline screenshot itself was misleading (see Done #1) — worth a fresh capture after fold-in.
