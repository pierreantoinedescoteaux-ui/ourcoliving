## Flags
- The baseline screenshot (`_qa/mshots/hope.png`) shows a large blank gap (~roughly the middle 70% of the page) between the first crisis item and the footer. This is NOT a mobile CSS bug: every `.hope-chapter`, `.crisis`, and `.crises-close` gets a `.reveal` class (opacity:0, translateY(24px)) in `renderHope()`, and only flips to visible via `IntersectionObserver` once scrolled into the real viewport. A single full-page screenshot capture without incremental scroll events never fires those observers for anything below the fold, so it renders as blank space that a real scrolling user would never see. Confirmed by reading the class structure and CSS (`.reveal`/`.reveal.in` in styles.css, IntersectionObserver wiring in app.js) rather than assuming — no fix applied, just flagging so it isn't mistaken for a real layout defect during the later live audit.
