## Proposed (not done)
- **Auto-advance should turn off on mobile (recipe 5).** The stage auto-advances every 28s via `setInterval` in `resetTimer()` (design.html inline script) regardless of viewport — it only checks `prefers-reduced-motion`, not screen width. Fighting a reader's own swipe/scroll every 28s on a phone is exactly what recipe 5 warns against. Fix requires a JS change (out of scope here): in `resetTimer()`, also skip starting the interval when `matchMedia('(max-width:760px)').matches`, same pattern already used for `reduced()`.
- No other structural/HTML/JS changes proposed — the carousel's tap-driven model (peeks + dots + arrow buttons, all click-based, no drag/scroll-jack) already works on touch without modification once the auto-advance above is addressed, so it doesn't need recipe 5's scroll-snap conversion or a recipe-6 fallback redesign.

## Flags
- **`.wback` "back to the tower" pill and the `.wmedia`/`img` "overflow" entries are a shared, site-wide component** (injected by `site-nav.js`'s world-band code, keyed to `design.html` via `PAGE_SCENE.design = "gardens"`), not something owned by `design.html`/`design-data.js`. They show up nearly identically across almost every page in `report.json` (story, work, project, map, type, resources, talkpieces, designers, themes, inspiration, detail), so this is a global site-nav.js/mobile.css issue, not a design.html-specific bug — flagging rather than patching it here to avoid a page-by-page band-aid on a shared component.
  - `site-nav.js` already has a `@media(max-width:640px)` rule that sets `.wback` to `.75rem` (12px), which is >= the floor — the `a.wback@9.6` in report.json may predate that fix; worth re-running the audit against current `site-nav.js` before treating it as still broken.
  - The `.wmedia`/`img` "overflow" entries come from the world-band's intentional `inset:-7% -3%` zoom effect, clipped by the ancestor `.wband{overflow:hidden}` — visually it doesn't bleed past the rounded band, the audit script is likely measuring the unclipped child's own bounding box (a script false-positive for any page using this component, not a visible bug).
- Didn't spot any broken images or JS errors specific to design.html in report.json (`imgIssues: []`, `jsErrors: []`) — the tiny-text count (43) was the only real signal, and it's fully accounted for by the five selectors fixed above.
