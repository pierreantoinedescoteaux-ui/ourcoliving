## Flags
- **Screenshot artifact, not a page bug:** `_qa/mshots/story.png` shows ~11,000px of blank cream space in the middle of the page (roughly y=2140 to y=13800 of a 14656px-tall capture). This is `.reveal` scroll-reveal (`opacity:0` until an `IntersectionObserver` adds `.in`) — the capture tool doesn't appear to scroll/wait long enough for below-the-fold sections to trigger, so most content past the vignette strip renders invisible in the static shot even though it's present and correctly laid out in the DOM. Confirmed this isn't story-specific: `about.html`'s screenshot shows the identical mid-page blank pattern using the same `.reveal` mechanism. I relied on the HTML/JS source + `about-data.js` content directly (not the screenshot) to verify layout for everything past the vignette strip, since the screenshot can't be trusted for that region. Flagging for whoever owns the mshot/audit tooling — worth having it force `.reveal.in` (or wait for the observer) before capturing, or the live audit will have the same blind spot for every `.reveal`-using page.
- `report.json`'s `tinyText` count of 1 (`a.wback@9.6`) likely undercounts for the same reason — several sub-16px/sub-12px violations I found by reading the CSS directly (chap-story p, v-line, b-line, c-sub, pillar description, v-ph ph-scene) sit inside `.reveal` sections that probably weren't visible/measured at capture time. Fixed all of them anyway based on static CSS math, not just what the report flagged.
