# work.html — mobile pass report

## Done
- Gallery grid: added explicit `grid-template-columns:1fr` — the existing `auto-fill(minmax(300px,1fr))` already resolves to 1 column at 390px, but breaks below ~340px viewports (300px card + 40px `.wrap` padding); this makes single-column explicit and safe down to smaller phones. Visible: every gallery card, screen 2 onward.
- Micro-label floor: bumped `.eyebrow`, `.gb-kicker`, `.chip`, `.exp-org`, `.exp-slots .sl`/`.sl b`, `.exp-go` to 12px — all were 9.9–11.5px, under the playbook's 12px micro-label floor. Visible: hero eyebrow (screen 1), gold band kicker (screen 1), filter chips (screen 1), every card's org/role line and "Read the case study" link (screen 2+), and the "Impact & KPIs / What it taught me" slots on non-clickable cards (e.g. Bridge2AI, MaRS, CanYouth cards).
- Filter chips: increased vertical padding to 13px so the ≥44px tap-target rule is met alongside the font bump (was ~30px tall). Visible: filter row, screen 1.
- Reading-text floor: bumped `.exp-blurb` (case-study card body copy) and `.close-sec .c-sub` (closing CTA subline) to 16px — were 14.4px and 15.2px, under the 16px body-text floor. Visible: the 3 case-study cards (Montréal, Dunbar, Shaughnessy) and the final screen before the footer.
- Fixed CTA email button (`.btn-pill`) clipping: the button is `inline-block` with no width cap, and `pierreantoinedescoteaux@gmail.com` has no spaces to wrap on — it was overflowing past the viewport edge and getting silently swallowed by the page's `overflow-x:clip` (no scrollbar, no visible error, just a truncated-looking button with part of the address invisible). Added `max-width`, `overflow-wrap:anywhere`, smaller font/padding so it wraps onto two lines instead. Visible: last screen, just above the footer.

## Proposed (not done)
- `report.json` flags a `div.wmedia` / `img` / `a.wback` overflow and a 9.6px `a.wback` tiny-text hit for `work.html` — but `work.html` has no entry in site-nav.js's `PAGE_SCENE` map, so the scene "back to tower" band (`.wbandwrap`/`.wband`/`.wback`) never mounts on this page. Confirmed against both the current baseline screenshots (`_qa/mshots/work.png`, `work-gallery-mobile.png`, `work-themes-mobile.png` — none show the band) and the mount logic in `site-nav.js` (`mountWorld()` returns early when `!PAGE_SCENE[f]`). This looks like stale/misattributed QA data (identical to `story.html`'s entries, which *does* have the band) rather than a real work.html defect — no CSS change made since the selectors don't exist in this page's DOM. If a scene is ever added to Work in the future: `site-nav.js`'s `WORLD_CSS` only re-sizes `.wback` at `max-width:640px`, leaving a gap at 641–759px where it'd fall back to the tiny 10.88px default — flag for whoever owns `site-nav.js`.
- `.wip-tag` CSS class (defined in this page's `<style>`, line 95) is dead code — `card()`'s `media()` helper never renders a `.wip-tag` element even though `it.wip` is computed and passed through. Not a mobile issue and not in scope here (would need a JS/renderer change), but worth a note to whoever owns `work.html`'s script block.
